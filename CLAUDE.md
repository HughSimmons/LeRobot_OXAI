# Project Instructions

## Subagent model selection

When delegating work via the Agent tool, assess how complex the task actually is before choosing a model rather than always defaulting to a higher-tier model. For simple, mechanical work — single-file lookups, straightforward searches, short summaries, or other tasks that don't require multi-step reasoning — pass `model: "haiku"` explicitly on the Agent call. Reserve Sonnet or Opus for subagent tasks that genuinely need judgment, synthesis, or multi-step reasoning.

## Project context

This repo turns an SO101 robot arm into a chess-playing robot: a PyBullet simulation/trajectory pipeline plans and scores pick-and-place moves, and a vision pipeline reads the board/pieces from a camera photo. Almost all active code lives under `lowlevel/`, which was reorganized (2026) for onboarding — read `lowlevel/README.md` first; it links to `lowlevel/coord_finder/README.md` (vision) and `lowlevel/kinematicscalibration/README.md` (PyBullet/URDF gripper-geometry calibration) for their sections. The root `README.md` just points into these.

Key structural facts:
- `lowlevel/` root holds the core library (`chess_traj.py`, `testkinematics.py`, `multisim_chess_fast.py`, `board_coordinates.py`, `continuous_xy_candidate_db.py`) and the canonical lookup-build/verify pipeline (`build_general_xy_lookup.py`, `verify_xy_lookup_move.py`, `build_general_nonh_reverse_lookup.py`, `verify_nonh_lookup_moves.py`, etc.) plus hardware-calibration probes. Everything else that was dead/superseded (an abandoned MuJoCo path, an abandoned two-camera vision prototype, square-specific one-off lookup builders, and the old `drafts/` scratch dir) was moved to `lowlevel/legacy/` — still present for reference, not imported by anything live. Before assuming a script is dead, check its actual importers; the exploration pass that planned this cleanup got it backwards once (`piece_from_square_crop.py` and `run_pipeline_test01.py` looked superseded by naming but are live imports of the canonical vision pipeline — verify the import graph, don't trust docstrings/naming alone).
- `lowlevel/paths.py` is the single source of truth for `URDF_PATH`/`ASSETS_DIR`/`REPO_ROOT`/etc. — never hardcode an absolute path to the SO-ARM100 assets; import from `paths` instead.
- Two conda envs cover this code: `IKsim_mj` (pybullet/pinocchio/meshcat/numpy, for `lowlevel/` sim+kinematics — env file `lowlevel/realsimenv.yml`) and `Live2FEN` (opencv/numpy/scikit-learn, for `lowlevel/coord_finder/` vision — env file `lowlevel/coord_finder/live2fen_env.yml`). Simulation scripts also need the vendored `lerobot` package on `PYTHONPATH=lowlevel/lerobot/src`.
- **Hardware safety (also a pinned memory, repeated here since it travels with the repo)**: the user runs all commands that move the real SO101 arm themselves — never invoke `run_real_so101_from_xy_lookup.py --execute`, `probe_xy_pose.py --execute`, or any other hardware-driving command. Stop at printing the ready-to-run command for the user. Dry runs (omit `--execute`), simulation, and calibration on saved images/data are fine to run directly.
